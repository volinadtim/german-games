# Правила работы в этом репозитории

Репозиторий для всех игр Германа. Публичный: https://github.com/volinadtim/german-games

## Процесс (обязательно)

1. **Оптимистичный поток.** После реализации задачи — сразу `git add` + `git commit` + `git push` в `main`. Без предварительных тестов и проверок, без веток и PR.
2. **Проверка после пуша.** Сразу после пуша проверяем результат (запуск/импорт в Godot, `cargo check`/`cargo run`, просмотр кода). Нашли проблему — чиним и снова сразу коммит + пуш.
3. Пользователь параллельно смотрит результат на другом компьютере (там работает `scripts/auto-pull.ps1`), поэтому пушить надо часто и маленькими шагами.
4. Коммиты — короткие, по-русски или по-английски, описывают что сделано.
5. **Ответ в `ANSWER.md`.** Сверху добавляем раздел `## ЧЧ:ММ — тема` (время промпта МСК из `prompts.ps1`, часы ПК не использовать): что сделано, что проверить, что не готово. Разделы старше суток удаляем. При rebase файл склеивается без конфликтов (`merge=union`).
6. **Скрипты вместо ручных цепочек.** Проверка — `scripts/gd-check.sh`, отправка — `scripts/ship.sh "msg" [файлы]`. Если одно и то же действие делается третий раз — оформить его скриптом в `scripts/`.

## Промпты из Telegram

- промпты: `C:\Users\volin\.config\atlas\prompts.ps1` (new/wait) — чат «промпты» через atlas.
- Слушает и раздаёт промпты программа `scripts/dispatch/dispatch.ps1` (см. ниже). Обычная сессия `new`/`wait` сама не запускает.
- Время в выводе — МСК с сервера; часы этого ПК спешат, их не использовать. Ключ из папки скрипта в репо не копировать.

## Стек

- **Godot 4** (GDScript) — игры в `godot/<игра>/`, у каждой свой `project.godot`.
  - Не коммитить `.godot/` (кэш). Файлы `*.import` и `*.uid` — коммитить.
- **Rust** — игры в `rust/<игра>/`, общий workspace в корневом `Cargo.toml` (`members = ["rust/*"]`).
  - Новая игра: `cargo new rust/<игра>`; запуск `cargo run -p <игра>`.
  - Для графики по умолчанию `macroquad` (простой), для крупных — `bevy`.

## Окружение

- Windows. Имена папок игр — `kebab-case`, латиницей.

## Диспетчер TG-промптов — программа (v1), не сессия Claude

Промпты Германа распределяет **программа** `scripts/dispatch/dispatch.ps1`, а не сессия Claude с субагентами.
Сессия-диспетчер (v2: одна сессия Claude раздаёт задачи субагентам) **не возвращать**: она теряла очередь по зонам
(один файл правили 20 агентов за день), учёт переделок, разрасталась до тысяч сообщений, а при её смене TG никто не слушал.
Сессия Claude сама TG не слушает и `tg-next.ps1` / `prompts.ps1 wait` не запускает — запуск диспетчера делает пользователь.

- Запуск (слушать TG): `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\dispatch\dispatch.ps1`
  Одна задача без TG (по-настоящему правит и пушит): `... dispatch.ps1 -Task "текст"`.
- TUI: `scripts\dispatch\tui.bat` — сессии воркеров, лента, контекст, модель/уровень, ввод задач, чат с агентом.
- Стоп: `scripts\dispatch\ctl.ps1 stop|kill|resume|status` (stop — мягкий: воркеры доделывают или пишут handoff).
- Как работает: промпт -> роутер (`claude -p` на Sonnet/low, текст `scripts/dispatch/router.md`) -> JSON: зона, агент
  `sonnet|opus`, `--effort`, `new|continue`, переделка (`redo`) -> воркер `claude -p --agent <агент>` в своей копии
  `.claude/worktrees/disp-<зона>`. Одна зона — один воркер (остальные задачи зоны ждут), зоны параллельно.
  Несколько задач в промпте — разбиваются; задачи одной зоны склеиваются одному воркеру. Sonnet ответил `СЛОЖНО` — та же
  задача уходит opus/high. Перед воркером строится карта кода (`scripts/codemap.py`). Лимит сессии Claude — задача не
  ошибка, возвращается в очередь, пауза 15 мин.
- Состояние: `.claude/dispatch/` в основной копии — `jobs.json` (очередь, читает TUI), `state.json` (сессия зоны),
  `history.jsonl` (задачи и переделки — статистика по моделям), `dispatch.log`.
- Зоны — в `router.md` и `$Zones` в `dispatch.ps1`; при новых зонах в `godot/THE LEAK/AGENTS.md` обновлять оба.
- **Рабочие копии и место на диске.** Создаёт и удаляет worktree только `scripts/dispatch/wt.js`: sparse без `Blender/`
  (~30 МБ вместо 2 ГБ), копия создаётся под задачу и удаляется после неё, если чистая и запушена; брошенные — через 6 ч.
  Перед созданием проверяется место: свободно на диске не меньше `minFreeGB` (8) и копии задач, созданные `wt.js`, не больше `maxGB` (6 ГБ) —
  иначе уборка, потом задача ждёт в очереди. Задача про модели Blender («Blender», «блендер» или `.blend` в тексте) — копия с
  `Blender/`. Настройки: `.claude/dispatch/wt-config.json`. Состояние: `node scripts/dispatch/wt.js status`, уборка: `reap`.
  Агентам создавать/удалять worktree через git и EnterWorktree запрещено (хук в `.claude/settings.json`).
