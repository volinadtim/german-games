Ты правишь игру eskiNess (Godot 4) в репо german-games. Все правила — здесь; `AGENTS.md` открывай, только если нужна таблица зон/файлов.

КАЖДЫЙ ШАГ ДОРОГОЙ: на каждом шаге заново перечитывается весь твой контекст. Цель — 5–10 шагов на задачу.
1. Поиск — ОДНИМ шагом: в одной Bash-команде сразу все слова по карте кода:
   `grep -n -i -E "слово1|слово2|слово3" "godot/THE LEAK/CODEMAP.md" | head -40` (строки вида `scripts/car/car_drive.gd:1077 at_trunk(g) — описание`, пути от godot/THE LEAK/).
2. Чтение — ОДНИМ шагом: все нужные куски сразу, несколько Read (offset/limit, ~40–80 строк вокруг нужной строки) в одном сообщении. Целиком большие файлы не читать. Не перечитывать то, что уже видел, и файл после своей правки.
3. Правки — ОДНИМ шагом: все Edit сразу в одном сообщении.
4. Проверка + коммит + ответ Герману — ОДНОЙ командой (gd-check запускается внутри, при ошибках ничего не отправит и покажет их):
   `ANSWER_AT="<время промпта>" ANSWER="что сделано; что проверить Герману" SHIP_MODEL="Claude Sonnet 5.5" scripts/ship.sh "коротко по-русски что сделано" <файлы>`
ship.sh выход 3 «КОНФЛИКТ В КОДЕ» — main ушёл вперёд в тех же местах: маркеры конфликта НЕ править и rebase вручную не делать. Переделай задачу на свежем main: `git fetch -q origin main && git reset -q --hard origin/main`, заново прочитай нужные куски, сделай правки, снова ship.sh.
Не делать: git pull (worktree уже свежий), ls, wc -l, cat ANSWER.md/AGENTS.md, отдельный gd-check перед ship, скриншоты, прогоны игры, тестовые скрипты. Длинный вывод режь (`| head -40`).
Новой функции — строка `## что делает` над ней (из неё строится карта). Не трогать сейвы игрока (user://save_*.json, settings.cfg). Ничего не скачивать.
Между шагами не пиши рассуждения — сразу вызывай инструменты. Ответ в конце — одна строка: хеш + что не проверено.
Если задача оказалась сложной (новая механика, сеть, много файлов) — сразу ответь `СЛОЖНО: <почему>`, ничего не коммить.
